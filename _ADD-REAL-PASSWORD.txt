HOW TO PROPERLY PASSWORD-PROTECT THE SUMMER 2026 ALBUM
======================================================

WHAT'S IN PLACE NOW
-------------------
A passcode screen on the homepage card and on summer-2026.html.
It stops casual visitors and keeps the album out of Google.

WHAT IT DOES NOT DO
-------------------
The photo files themselves are still reachable by direct URL. Anyone who
knows or guesses a path like

    https://your-site.com/summer-2026/waterwars-3.webp

gets the photo without ever seeing the passcode screen. A visitor who
opens "View Source" can also read the passcode check and work around it.

This is a limitation of any passcode done in the page itself. Real
protection has to happen on the server, before the file is sent.


OPTION 1 — .htaccess  (Apache hosts: most cPanel/shared hosting)
---------------------------------------------------------------
Ask your host if they support .htaccess and "Directory Privacy" or
"Password Protect Directories" in the control panel. Most cPanel hosts
have a point-and-click tool for it — no files to edit.

Doing it by hand: create a file named .htaccess inside summer-2026/

    AuthType Basic
    AuthName "Summer 2026 Photos"
    AuthUserFile /full/path/to/.htpasswd
    Require valid-user

Your host's control panel will generate the .htpasswd file. The full
path must be the server path, which your host can tell you.

This protects the actual image files, not just the page.


OPTION 2 — Host's built-in protection
-------------------------------------
If you're on Netlify, Cloudflare Pages, Vercel or similar, look for
"Password protection" or "Access control" in the site settings. Usually
a single toggle plus a password. This is the easiest reliable option.

Note: GitHub Pages does NOT offer password protection on free plans.
If this repo publishes via GitHub Pages, Option 1 is not available
either (no .htaccess support). In that case the practical choices are
to move the album to a host that supports it, or accept that the photo
files are publicly reachable by direct URL.


OPTION 3 — Leave as-is
----------------------
Reasonable if the photos aren't sensitive and you mainly want to keep
the album off search engines and away from casual browsing. The
noindex tag on summer-2026.html already handles the search engine part.

Worth thinking about, since these are photos of children: how much does
it matter if a determined stranger could reach them? If the answer is
"quite a lot", use Option 1 or 2.


CHANGING THE PASSCODE
---------------------
Current passcode: abc2026oe

It's stored as a SHA-256 fingerprint in two places:
    index.html        -> PASSCODE_HASH
    summer-2026.html  -> PASSCODE_HASH

To change it: open summer-2026.html in your browser, press F12 for the
console, run   sha256('your-new-code')   and paste the 64-character
result over BOTH PASSCODE_HASH values. They must match.
